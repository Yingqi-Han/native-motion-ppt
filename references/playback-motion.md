# 真实录屏的运动分析

check_native_motion.py逐帧读取真实桌面录像，不调用源码的动画求值器。它拒绝代码设计视频，以及与PPTX或录屏校验值不一致的证据。

```bash
python scripts/check_native_motion.py player-recording.mp4 --pptx deck.pptx --evidence playback-evidence.json --spec project.json --plan playback-plan.json --references qa/native/rendered --out qa/motion
```

一键入口已自动执行此步骤。输出native-motion-playback-audit.json、observed-playback-plan.json、held-XX.png和motion-report.html。报告无需服务器；点运动曲线或异常时间可以定位录像。导出报告时保留相对目录和player-recording.mp4。

若浏览器限制直接打开本地文件，可使用本地预览服务器。它支持视频字节范围读取，避免只能从头播放：
```bash
python scripts/serve_report.py <运行目录> --port 3021
```

## 观察动作和停稳

按真实PTS逐帧解码320×180缩略画面，记录局部图像变化，合并短暂重绘间隔。源放映安排只确定页面输入顺序和候选区间，动作起止来自实际像素变化。

每页用实际Office参考找到持续至少450ms的稳定匹配区间，再在最后一个可信区间选取标定帧。没有可信区间时保留待检查，不能用固定等待时间宣称已经停稳。缩略图会漏掉细微运动，所以主体还要在原始分辨率下单独追踪。

观察计划与本次PPT、录像、源JSON和输入安排的校验值绑定。后续到位比较与关键帧抽取采用观察计划，并加入动作起止和峰值速度附近的真实帧。

## 追踪对象

- 数据角色、纯色矩形、单一向上擦除：柱顶/底用中心10px色带测量，另存轮廓尺寸，检查底边偏离与反向回弹。动作识别依据柱顶，边缘宽度的栅格变化不当作继续运动。
- 有move动作的独立矩形、椭圆和组合几何：由实际到位帧标定背景与轮廓，在原始捕获分辨率追踪位置和尺寸。参考主体附近的连通区域用于排除标题和箭头；实际轨迹保留像素量化误差。
- 源路径仅用于保守搜索范围和单向/闭合/自由曲线意图，不产生录像位置。闭合路径正常往返不能被当作回弹。
- 旋转、缩放、明显透明或遮挡、难以隔离的轮廓保留待检查；不能把失去目标或静止画面写成动画通过。

默认主体最大帧间变化24px、柱底误差1px、单向回退2px。明显跳变或柱底漂移为失败；中途停顿、局部速度突增、可见性或采集缺口提示复查。默认停顿阈值300ms，需前后都有运动，不把首尾缓动停稳当作中途卡顿。声明的分步停顿可能触发复查，由设计意图决定是否修正。

速度用±80ms真实时间戳的局部线性拟合；加速度由该速度计算。两者是诊断量，受轮廓量化和压缩影响，不是“流畅度评分”。报告同时保留原始轮廓、PTS和帧号，未插帧或补造播放器重绘。

## 定位和修复

诊断记录含页码、源对象名、原生shape id、录像时间、原始帧号、阈值和建议。先回看对应真实画面，再改源码/原生动作，重新导出并录制；不能只改报告中的通过状态。

默认一键后端为 Impress，其淡切回退不能证明原生 Morph。WPS 独立入口与没有对象动画的隔离诊断见 wps-playback.md。页面分析窗口必须截止于真实转场开始；到达页码标签可能出现在 Morph 中途，不能用其出现时刻作为上一页漂移动作的结束。


v1.6.0 的 check_playback_phases.py 从真实参考匹配和像素轮廓推导阶段计划；check_native_motion.py 可用 --phases 消费已绑定的阶段证据，保留 raw_status/raw_issues 与分段后的结果。源颜色/静态框限定搜索，不产生录像坐标。状态和只检查复验见 acceptance.md。

v1.7.0 修正自动首屏晚展开导致的扫描窗口截断：稳定参考用于确认页面身份，首屏分析窗口则从与实际 F5 记录相交或之后的首个画面活动区间开始，覆盖早期主体和数据柱。媒体 PTS 与输入 wall-clock 有启动偏移，因此这表示保守分析窗口，不声称是播放器内部的精确入场时间。新版阶段记录绑定采集 JSON 的 SHA 和实际 show-key 时间；没有足够活动证据时保持待检查。旧录像的复算写入新的 check 运行，原始待检结果继续保留。
