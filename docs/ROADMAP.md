# 后续优化路线

优先选择可复现的实际项目问题，每轮保留输入、对应实现、自动结果和真实播放证据。新版本独立发布，历史结果不覆盖。

## v1.7：第一次使用与通用场景

- 从只安装核心依赖开始完成项目创建、双版导出、预览生成和已有 PPT 增强。
- 按任务诊断依赖、浏览器和字体，避免缺库时连帮助都无法读取。
- 产品介绍与项目进展示例保留可编辑输入、原生动作及 WPS 实播。
- 自动首屏的晚展开不应截断早期运动，复验绑定实际 F5 与原始录像。
- 独立矩形/椭圆不再被已消失的旧页标签框裁切；原始失败测量与正式检查状态保持一致。
- Windows UTF-8 预览读取、Linux 中文字体及跨版本受管理升级均单独验证。

## 下一轮：检测覆盖与真实输入

- 收集经过授权的实际项目，用失败样本和正常样本同时约束同色干扰、组合主体与局部遮挡。
- 明确区分“可测”“不支持”“内容尚未完整出现”，为每个待检原因给出具体复验步骤。
- 先增加可复现的原生故障对照，再考虑扩展轮廓算法；不靠放宽阈值增加通过率。
- 优化已有 PPT 的分组计划制作，让对象清单、语义分组和原稿保留更容易检查。

## 需要独立环境的工作

- Windows WPS 和 Microsoft PowerPoint 的真实 GUI 验收需要对应机器、版本和录屏；Windows 核心 CLI CI 只认证导出与预览生成。
- 文本 Morph、任意旋转、透明和复杂遮挡需要新的可测方法和实际播放器证据，现阶段保留待检查。

GitHub CI 负责可重复的源码、最小依赖和打包检查；实际播放器结论仍来自每轮独立实录与审阅。
